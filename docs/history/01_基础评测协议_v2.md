# 评测工作流（协议 v2）

## 客观题（旧入口，保留）

默认数据为 `datasets/objective_70/questions.jsonl`。文本模型使用 `--text-only` 评测62道无图题；确认支持图片输入后才评测全部70题。结果逐题追加到新 `runs/objective/<run>/`，随后用 `rescore_qwen_mini.py` 本地重评分。

```powershell
$env:DASHSCOPE_API_KEY = "运行时密钥"
.venv\Scripts\python -m CampusEval.scripts.evaluation.evaluate_qwen_mini `
  --model <model-id> --text-only --output-dir CampusEval/runs/objective/<run>
```

## 主观题

1. 被测模型答案单独生成或准备为 JSONL（`answer_id / question_id / answer / candidate_model`），不与 Judge 调用绑定；生成入口 `scripts/evaluation/generate_subjective_answers.py`。
2. Rubric：`datasets/subjective_50/rubrics.jsonl`（新三字段：`rubric` 纯文本评分标准 + 两种参考解法）；当前为统一实验性20分，不是官方题目分值。
3. Judge 盲评：只提供题目、纯文本 Rubric、两种参考解法与被测答案；不暴露被测模型身份、其他 Judge 结果、Rubric 生成元数据或历史结果。
4. Judge 输出为整体评分（不再逐分项）：`score / max_score / reason / correct_parts / errors / evidence_quotes / confidence / needs_human_review`。边界校验：`0 <= score <= max_score`、分数为数值、`reason` 非空、`question_id` 必须存在于主观题集；高分含严重错误或低置信度时强制人工复核。
5. 多 Judge 配置化：默认三 Judge（`configs/subjective_evaluation.json` 的 `default_judge_mode`），单 Judge 用 `--judge-mode single`；分歧超阈值、面板不完整、任一 Judge 要求复核 → 进入人工复核队列。
6. 所有新运行只写入 `runs/`；`--dry-run` 零网络请求。

```powershell
.venv\Scripts\python -m CampusEval.scripts.evaluation.evaluate_subjective_answers `
  --answers <answers.jsonl> --dry-run

.venv\Scripts\python -m CampusEval.scripts.evaluation.evaluate_subjective_answers `
  --answers <answers.jsonl> --execute `
  --base-url "$env:SUBJECTIVE_LLM_BASE_URL" --judge-mode three

.venv\Scripts\python -m CampusEval.scripts.evaluation.aggregate_subjective_scores `
  --answers <answers.jsonl> `
  --judgments runs/subjective/judgments/judgments.jsonl --output-dir <aggregate-dir>
```

主观题摘要至少报告平均得分率、满分率、逐题得分率、Judge 一致性（平均分数极差比）、人工复核率、token 和耗时。API Key 仅允许通过运行时环境变量提供。
